Networking

Networking Protocols

Networking protocols define how hosts identify each other, exchange data, authenticate sessions, and route traffic across networks. In security work, protocol knowledge helps analysts distinguish legitimate behavior from scanning, spoofing, tunneling, credential abuse, or protocol misuse.

Core concepts

TCP/IP and the layered model

TCP/IP is the practical foundation of modern internet communications. IP is responsible for addressing and routing packets, while TCP provides reliable, ordered delivery and connection management. UDP offers connectionless transport for latency-sensitive traffic like DNS, VoIP, and streaming.

TCP handshake and state

TCP uses a three-way handshake: SYN, SYN-ACK, ACK. This creates a connection before data transfer, which makes it useful for file transfer, web browsing, and remote access. Security teams monitor for abnormal connection bursts, half-open sessions, or unusual ports to detect scanning or service abuse.

UDP and low-latency traffic

UDP is simpler and faster because it does not require connection setup or retransmission. It is widely used by DNS, NTP, DHCP, SNMP, and real-time media. Its lack of reliability and handshake also gives attackers room to spoof traffic, flood endpoints, or hide command-and-control channels.

HTTP and HTTPS

HTTP is the application-layer protocol for web requests and responses. HTTPS adds TLS encryption, which protects content in transit. Analysts still inspect metadata like domains, timing patterns, certificate characteristics, and endpoint behavior because encrypted protocols can still reveal malicious use.

DNS

DNS resolves names to IP addresses and is a critical service for nearly every application. It is also a frequent attack surface for phishing, tunneling, malware beaconing, and exfiltration. Security teams watch for high-volume lookups, suspicious domain generation, fast-flux patterns, and unusual external resolutions.

DHCP

DHCP leases addresses automatically and can be abused by rogue servers. A malicious DHCP server can set a victim’s gateway or DNS server to attacker-controlled infrastructure, creating a man-in-the-middle path. Defense includes switch port security, DHCP snooping, and validation of legitimate server responses.

ARP and local layer attacks

ARP maps IPs to local MAC addresses. Attackers can poison ARP tables to redirect traffic or intercept sessions inside the same subnet. This is especially relevant in flat or poorly segmented networks where local hosts trust one another too easily.

SSH, Telnet, and remote administration

SSH is the standard encrypted method for remote administration. Telnet is outdated and insecure because it sends credentials and terminal data without encryption. Modern security baselines should prohibit Telnet and closely review SSH login behavior, unusual forwarding, and source IP reputation.

FTP, SMTP, POP3, and IMAP

FTP historically exposes credentials in clear text; SMTP handles email messaging; POP3 and IMAP control mail retrieval and synchronization. These protocols often appear in operational environments and should be checked for unencrypted traffic, unusual bulk transfers, or repeated authentication failures.

ICMP and NTP

ICMP is used for diagnostics and connectivity checks, while NTP synchronizes clocks across systems. Attackers abuse ICMP for tunneling or covert channels and can use NTP to facilitate reflection or amplify traffic. Secure network design should also monitor for unexpected ICMP scanning and drifted system time.

SNMP and management plane risk

SNMP is used to monitor and configure devices, but weak community strings or exposed write access can expose topology and allow device changes. In many environments, SNMPv3 with strong authentication and ACLs is the correct baseline.

Routing protocols

RIP and OSPF enable route sharing inside networks, but unauthorized route advertisements can redirect traffic or create loops. Proper authentication, trunk filtering, and route validation reduce the chance that a malicious actor alters network paths.

What analysts look for

  • Unexpected outbound connections to uncommon domains, especially with DNS query bursts or long-lived beacons.
  • Repeated failed or successful logins across SSH, RDP, SMTP, or VPN services outside normal business hours.
  • Large file transfers over FTP, SMB, or web protocols that do not match business usage.
  • Rogue DHCP or ARP replies that change gateway or DNS settings on a segment.
  • Port scans, SYN floods, and abnormal ICMP or SNMP traffic inconsistent with the environment.

Verified references

  • National Institute of Standards and Technology (NIST) guidance on network security, log monitoring, and incident response.
  • CISA and NSA guidance on secure network architecture and protocol hardening.
  • OWASP guidance on web application and transport-layer security patterns.

Key takeaways

  • TCP provides reliability; UDP is faster and lighter.
  • DNS, DHCP, and ARP are classic network-layer abuse points because they are foundational and often trusted.
  • HTTPS hides content but not all metadata; behavior still matters.
  • Segmentation, strict ACLs, and strong authentication materially reduce lateral movement risk.
