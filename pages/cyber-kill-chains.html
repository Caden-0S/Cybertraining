Threat Modeling

Cyber Kill Chains

The cyber kill chain is a model that explains how an intrusion tends to progress from initial planning to execution and impact. It is a useful framework for defenders because it highlights interruption points: early prevention is usually cheaper and safer than responding after a breach has spread.

Core concepts

Reconnaissance

The adversary identifies targets, internet-facing services, employees, and weak points. This can include open-source intelligence gathering, employee profiling, or recon using internet exposure, leaked credentials, or public infrastructure.

Weaponization

The attacker prepares malicious content or exploit code designed to trigger execution when delivered. This may involve custom malware, document-based payloads, or exploit chains that blend social engineering with technical execution.

Delivery

Malicious content reaches the victim through phishing, malicious links, drive-by downloads, software supply chain compromises, or removable media. Because delivery is where human behavior becomes part of the attack path, awareness and filtering matter a great deal.

Exploitation

The target system is tricked into running a malicious payload or exploiting a vulnerability. This stage transitions from malicious content to actual code execution on the victim host or service.

Installation

Once execution is established, the adversary installs persistence such as a service, scheduled task, registry run key, or malicious script. Installation helps the attacker survive reboot and continue operating even after initial access appears to be cleaned up.

Command and control

Malware begins beaconing out to attacker-controlled infrastructure, receiving instructions, or downloading additional tools. C2 traffic is often low-volume, regular, and disguised as normal application traffic such as HTTP, HTTPS, or DNS.

Actions on objectives

This final stage includes credential theft, privilege escalation, discovery, lateral movement, data collection, or destructive actions. The attacker is no longer just trying to get in; they are executing the purpose of the intrusion.

Where defenders interrupt the chain

  • Block or reduce entry vectors: secure email gateways, application patching, phishing awareness, and external exposure reduction.
  • Hunt for execution and persistence: suspicious PowerShell, scheduled tasks, services, and privilege abuse.
  • Monitor network traffic for beaconing and C2: unusual domains, regular intervals, and abnormal outbound destinations.
  • Contain at the first sign of lateral movement or credential theft before exfiltration or destructive impact occurs.

Verified references

  • Lockheed Martin’s cyber kill chain model and later extensions from threat intelligence and incident response practice.
  • MITRE ATT&CK as a modern, behavior-based alternative to linear kill-chain thinking.
  • NIST guidance on intrusion analysis and response lifecycle.
  • CISA and industry playbooks describing intrusion progression, detection opportunities, and containment priorities.

My notes

Write down interruption points, telemetry, and response questions for each stage.

Key takeaways

  • Kill-chain thinking helps defenders connect early, mid, and late-stage events rather than treating each alert in isolation.
  • Detection should focus on meaningful transition points between stages, not just on malicious hashes alone.
  • Real intrusions rarely follow a perfect sequence; the model is still useful as a mental map for investigation and response.
